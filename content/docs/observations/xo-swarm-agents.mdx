## Goal

Design a tiny swarm that can be triggered quickly from CLI, where each agent sees only one folder.

## Architecture

The swarm uses shell scripts and static config:

- Dispatcher: `swarm/xo-swarm.sh`
- Agent map: `swarm/agents.env`
- Prompts: `swarm/prompts/x.md`, `swarm/prompts/o.md`
- Runner contract: `swarm/runners/local-runner.sh`
- Logs: `swarm/logs/`

This design keeps startup cost low and avoids heavy orchestration layers.

## Agents

### Agent X

- Intent: expansion and coverage
- Scope folder: `content/docs/observations/xo-swarm-frontend`
- Prompt: `swarm/prompts/x.md`

### Agent O

- Intent: cleanup and organization
- Scope folder: `content/docs/agent-harness`
- Prompt: `swarm/prompts/o.md`

## Trigger model

From repo root:

```bash
pnpm swarm
pnpm swarm:x
pnpm swarm:o
```

or direct:

```bash
./swarm/xo-swarm.sh all "scan and report"
./swarm/xo-swarm.sh x "summarize missing docs"
```

## Folder-only constraints

Scope is enforced by three controls:

1. Static folder mapping in `swarm/agents.env`
2. Run envelope includes explicit scope contract
3. Runner receives target folder as isolated working target

The default runner writes scope contracts and run envelopes to logs. Replace its final commented command with your preferred Cursor agent CLI invocation.

## Runner contract

Dispatcher calls runner as:

```bash
runner <agent_name> <folder_abs> <prompt_file> <task> <log_file>
```

This allows swapping execution engines without changing swarm topology.

## Why this is lightweight

- No queue service
- No database
- No persistent worker process
- One command starts both agents in parallel
- Plain text logs for auditing

## Suggested next step

Connect `swarm/runners/local-runner.sh` to your exact Cursor agent CLI command and enforce `cd "$folder_abs"` before execution so path scope is hard-bound at runtime.
