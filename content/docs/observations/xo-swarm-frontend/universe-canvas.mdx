A project of `type: "local"` renders as an infinite pan/zoom deep-space canvas instead of
a chat. Every file becomes a celestial body sized by its bytes, and the view reacts in real
time to changes on disk. This is the local-first experiment layered onto the platform app.

## The data model

`lib/universe.ts` is the single source of truth for what is drawn:

- `DATA_VISIBILITY_THRESHOLD = 100KB`. Files smaller than this are invisible on the canvas
  (they still exist on disk).
- `dataAccent(name)` marks two always-visible exceptions: a **README** renders as a red
  mass, a **SIGNAL** renders as a green mass, regardless of size.
- `isDataVisible(name, size)` is `size >= threshold || isAccent`.

A particle is a top-level entry. `app/actions/projects.ts` produces `ProjectFile[]`
(`path, name, size, type`). A folder's size is the recursive aggregate of its contents,
ignoring `.git`, `node_modules`, `.next`, dot-entries, capped at depth 12. Nested changes
roll up to the top-level entry.

## Rendering: `components/projects/DeepSpaceCanvas.tsx`

### Layout (phyllotaxis spiral)

Visible files are sorted by path and placed on a golden-angle spiral so positions stay
stable when sizes change (editing a file moves only its own dot's size):

```
GOLDEN_ANGLE = pi * (3 - sqrt(5))   (~137.5 degrees)
SPIRAL_SPACING = 140 px
radius   = SPIRAL_SPACING * sqrt(index + 0.5)
angle    = index * GOLDEN_ANGLE
diameter = MIN_DOT * (size / 100KB)   with MIN_DOT = 18 px
```

Camera state is `{tx, ty, scale}` with `MIN_SCALE = 0.02` and `MAX_SCALE = 8`. Drag to
pan, wheel to zoom toward the cursor, toolbar buttons to recenter and to jump to preset
zooms (nonce-driven).

### Body shapes

- **File mass** (`FileMass`): a lit sphere with a gravitational halo and two breathing
  rings. Color by accent: red (`#ff5a5a`) for README, green (`#4ade80`) for SIGNAL, blue
  (`#a9c6ff`) default. Openable files get a hover ring.
- **Galaxy** (`GalaxySystem`): folders render as a bright core (44% of diameter) with 3 to
  9 faint orbital rings and small orbiting bodies (14 to 40s periods), plus a soft disk
  glow.
- **ASCII banner** (`lib/ascii-banner.ts`): the folder name as a dim, breathing,
  center-screen block-letter banner (A-Z, 0-9, `-`, space).

### Modal viewers

Top-level `.md` and `.html` entries are clickable. Markdown renders through a styled
markdown view; HTML renders in a sandboxed `iframe`. Content is read by
`getProjectFileContent` (max 5MB, with a path-traversal guard).

## The live watcher (SSE)

`app/api/projects/[projectId]/watch/route.ts` opens an `EventSource` stream:

- Server side uses Node `fs.watch` recursively, ignoring `.git`, `.next`, `node_modules`,
  and dot-entries.
- Changes are aggregated to their **top-level entry** and debounced per entry at ~150ms.
- Events: `{ type: "change" | "rename" | "removed", path, name, size, delta, ts }`. A
  `connected` event opens the stream; a 25s heartbeat comment keeps it alive.

### File change to cosmic-ray flare, end to end

```
1. file write on disk
2. fs.watch fires (change | rename)
3. aggregate to top-level entry, debounce 150ms
4. SSE emits {type, path, size, delta, ts}
5. browser EventSource handler bumps a per-path nonce
6. CosmicRayField mounts keyed by that nonce
7. flare renders ~4500ms (FIELD_DURATION_MS): 18 rotating rays,
   2 expanding shock rings, a pulsing core, whole field spins ~9s
8. after the timeout, if the nonce was not superseded, the field clears
9. a debounced (~250ms) getProjectFiles() refresh resizes the dot in place
```

The nonce guard means the newest event for a path always wins and stale animations never
linger.

## The four forces

If XO is the particle, Energy / Time / Size / Lifespan are the forces acting on it. Two
describe work (the X face), two describe the record (the O face).

### Energy (work in motion)

An Energy session is a timed, headless `claude` run you start from the app.
`app/actions/energy.ts`:

- `startEnergySession(projectId, purpose, {baseRef?})` creates `.energy/<id>/`, writes
  `meta.json` (status `running`), snapshots the live tree into a commit, adds a git
  worktree on an `energy/<id>` branch under `os.tmpdir()/xo-energy/<id>`, then spawns
  `claude -p "<purpose>" --dangerously-skip-permissions` detached, stdio piped to
  `output.log`.
- It is force-stopped after `SESSION_MS = 5 minutes`, or ends when the agent exits. The
  status flips to a terminal value (`completed`, `failed`, `ended (timeout)`, `exited (code)`).
- `listEnergySessions` returns live ones (running and inside the 5-minute window),
  `listCompletedEnergySessions` / `listPastEnergySessions` the rest.
  `getEnergySessionDetail` returns elapsed / remaining / impact / the captured log.
  `getEnergyState` returns `{active, count}` for background polling.

While at least one session is live, the whole app shimmers: `getEnergyState` is polled
(~4s), the count is published into `lib/presence-store.ts`, and `components/presence-waves.tsx`
draws a slow drifting overlay (the canvas background also drifts via two blurred blobs).

### Time (how the app records)

The app has its own observer, a **server-side** recorder that survives HMR.
`lib/time-recorder.ts` keeps a `globalThis` singleton `{ recorders, timers, codes }` whose
interval runs in the Next server process (built for a long-lived `next dev` / `next start`,
not serverless). `app/actions/time.ts` exposes start / stop / status and `getTimeHistory`.

Key invariants:

- **Snapshot target is the entire xo-swarm repo** (`process.cwd()`) on the current branch,
  not the project subfolder. `lib/time-snapshot.ts` `commitSnapshot` does the commit.
- **Start/Stop code is append-only.** Start appends `0`, Stop appends `1`; it is never
  reset, only extended (`0` -> `01` -> `011`). Commits are `Start Time:<code>:` and
  `Stop Time:<code>:` (forced with `--allow-empty`). Interval ticks commit
  `auto snapshot #N` only when the tree changed.
- Persistence is two gitignored files, rehydrated and re-armed on restart:
  `.time-recorders.json` (active recorders) and `.time-codes.json` (the codes).

Gotcha: a stale `globalThis` registry across HMR once broke "Start Time" when a new field
was added without backfilling. `registry()` now backfills missing fields; keep that guard
when adding fields. Concurrent commits can also race on `.git/index.lock`; commits are
fire-and-forget so the action does not fail, but a snapshot can intermittently miss, and
the recording branch fills with high-volume auto-snapshot commits.

### Size (mass at rest)

`app/actions/size.ts` `getProjectSize` runs `du -sk` on the project folder. The
`ProjectSize` header stat polls it every 30s and humanizes the bytes.

### Lifespan (accumulated age)

Lifespan = commit count times the chosen unit, where the unit is the recorder shutter
speed in minutes (`lib/time-unit-store.ts`). `ProjectLifespan` polls `getTimeHistory`
every 30s, multiplies, and shows the result with an infinity glyph (the universe keeps no
upper bound). `lib/universe-age-store.ts` tracks the unit count, which also drives the
breadcrumb's opacity fade.

## Listing particles in the sidebar

`app/actions/xo.ts` merges two sources so the same particles read three ways (canvas,
live list, history):

- `listXoParticles` (live): live Energy sessions plus present `xo.py` worktrees, parsed
  from `git worktree list --porcelain`, filtered to `xo/XO-<timestamp>` branches.
- `listPastXoParticles` (past): finished Energy sessions plus prunable (dead) worktrees,
  newest-ended first, using the `prunable` flag to tell live from dead.

`components/nav-xo-particles.tsx` (`variant="live" | "past"`) polls every 5s, pulses a lime
mark (`#83d63a`) for live and a hollow mark for past, and routes clicks to the right pane.

## Canvas panes

`lib/canvas-split-store.ts` holds `open: Pane[]` capped at two of `live | time | files`
(opening a third evicts the oldest), plus `toggle*` / `show*` actions. The toolbar (Space
dropdown, Time tab, Recenter, Zoom) and the sidebar trees toggle the **same** flags:
Footprint drives `files`, Timeline drives `time`, so header, toolbar, and sidebar stay in
sync. `components/projects/LocalProjectView.tsx` is the tabbed Space / Files / Time shell;
when Files opens, the canvas splits in half.

## Particle vocabulary (Terra and Nova)

The repo names the two faces of the particle. **XO Terra** "takes space": a file or folder
at rest, the O face, drawn as a mass or galaxy. **XO Nova** "expands space": a running
`claude` agent (an Energy session), the X face, whose edits land as new Terra. Add Data
(Terra) lives on the left rail; Add Energy (Nova) on the right.

## Constants and timings

| Constant | Value | Meaning |
| -------- | ----- | ------- |
| `DATA_VISIBILITY_THRESHOLD` | 100 KB | minimum drawn file size |
| `MIN_DOT` | 18 px | diameter at the threshold |
| `GOLDEN_ANGLE` | ~137.5 deg | spiral angle |
| `SPIRAL_SPACING` | 140 px | spiral radial spacing |
| `FIELD_DURATION_MS` | 4500 ms | cosmic-ray flare lifetime |
| `SESSION_MS` | 5 min | Energy session hard cap |
| watcher debounce | ~150 ms | per top-level entry |
| folder scan depth | 12 | max recursion |
| `MIN_SCALE` / `MAX_SCALE` | 0.02 / 8 | zoom limits |
