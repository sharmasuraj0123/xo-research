`xo-swarm` is the platform UI of XO: the web app that launches and manages Coworker
workspaces. Internally the package is still named **`eliza-agent-builder`**, and the
codebase shows its history: an Eliza character builder and Coder deployment dashboard,
onto which a local-first **"universe" visualization** was later layered. Both halves
live in the same app today.

These notes are a code-level reference, written from a full sweep of
`app/`, `components/`, `lib/`, `hooks/`, and the API routes. They describe what the
frontend actually does, not what the README claims.

## The two halves

The app is really two products sharing one shell:

1. **The platform builder (the original product).** Sign in, create a project, build an
   Eliza character through a multi-step form, deploy it onto a Coder workspace, chat with
   it through 20+ agent "contexts", manage secrets / knowledge / billing. This half talks
   to several external backends (an agent backend, a billing backend, Coder, S3, Linear).

2. **The universe (the local-first experiment).** A project of `type: "local"` does not
   open a chat. It opens an infinite pan/zoom **deep-space canvas** where files are glowing
   masses, folders are galaxies, agent runs are "Energy" sessions, and git history is
   "Time". This half is self-contained: a folder plus a git repo is enough.

A single `ConditionalLayout` chooses which experience renders, and the same mirrored
sidebar component drives both.

## Tech stack

| Concern | Choice |
| ------- | ------ |
| Framework | Next.js App Router, React 19, server components + server actions |
| Styling | Tailwind (v4, oklch tokens), shadcn/ui (`new-york` style), Radix primitives, Lucide icons |
| Client state | Zustand (12 small stores) |
| Data / ORM | Drizzle ORM over PostgreSQL (`DATABASE_URL`) |
| Auth | Clerk in platform mode; a **Clerk-free shim** (`lib/auth-client.tsx`, `lib/auth-server.ts`) in the current local mode |
| AI | Vercel AI SDK (`ai`, `@ai-sdk/react`, `@ai-sdk/openai`) for chat streaming |
| Files | AWS S3 (`@aws-sdk/client-s3`) behind server routes |
| Integrations | Linear SDK, WhatsApp (Baileys), Stripe (via a billing backend), Coder REST API |
| Real-time | Server-Sent Events (filesystem watcher), interval polling (5 to 30s) |

## The one thing to know first

The app runs in two modes and the code is littered with both. In **local mode** (the
universe experiment) auth is fully stubbed: `lib/auth-client.tsx` returns a signed-out
user, `Protect` renders its children unconditionally, `SignIn` / `SignUp` / `PricingTable`
render `null`, and every project is owned by the literal string `"x"`. In **platform
mode** the same call sites expect real Clerk, real subscriptions, and real per-user Coder
credentials. When you read a component that calls `useUser()` or wraps content in
`Protect`, check which shim is in the import graph before assuming a behavior.
