## The shell: one layout, three modes

`app/layout.tsx` (server component) wraps everything in a provider stack and then hands
off to a single client dispatcher:

```
ThemeProvider (next-themes, default "dark", class strategy)
  -> ClerkThemeProvider (now a transparent passthrough)
    -> Sonner <Toaster/>
      -> ConditionalLayout
```

Fonts are Geist Sans / Geist Mono. `next.config.ts` sets `output: "standalone"`,
`serverActions.bodySizeLimit: "100mb"` (large uploads land via server actions),
`serverExternalPackages: ["@whiskeysockets/baileys"]` (WhatsApp can't be bundled), and
allows `img.clerk.com` remote images.

### `components/conditional-layout.tsx` (client)

This is the router for layout shape. It reads `usePathname()` and picks one of three:

| Mode | Paths | Renders |
| ---- | ----- | ------- |
| Auth | `/sign-in`, `/sign-up` | Centered auth card, floating theme toggle, no sidebar |
| Minimal | `/subscription/{success,failure}`, `/payment-method/{success,failure}` | Bare children, no chrome |
| Full | everything else | Mirrored dual-sidebar + header + `Protect`-wrapped content |

In full mode it mounts **two** `SidebarProvider` instances and the same `AppSidebar`
component twice, once `side="left"` and once `side="right"` (the right one only when a
project is open). It tracks `leftOpen` / `rightOpen` and makes them mutually exclusive:
opening one collapses the other. The right provider uses `display: contents` so it does
not introduce a competing flex context.

The header is assembled here, not in a page:

- Left cluster: sidebar trigger, a "Project" button, an **Add Energy** dialog (calls
  `startEnergySession`), and `ProjectSize`.
- Center: `DynamicBreadcrumb` (the `Universe {projectName}` label).
- Right cluster: `ProjectLifespan`, an **Add Timeline / Add Data** dialog, `ShareProjectButton`,
  a Configure dialog, and the right sidebar toggle.

The main content area is wrapped in `Protect`. In platform mode the condition checks
`user.publicMetadata.role` against `{basic, pro, enterprise}` and falls back to a pricing
table; when `DISABLE_AUTH` is set (or on `/`, `/templates`) the gate is bypassed.
`getProjectIdFromPath()` parses the project id out of `/projects/[id]` by segment position
and returns null on `/projects/create` and `/`, which is how the Configure / Share buttons
hide themselves off a project.

## The auth shim (current local mode)

Two files replace Clerk so the app builds and runs without it. This is the single most
important thing to understand before reading any gated component.

### `lib/auth-client.tsx` (client shim)

> Comment in the file: "DISABLE_AUTH is effectively always true here."

- `useUser()` returns `{ isLoaded: true, isSignedIn: false, user: null }`
- `useAuth()` returns `{ isLoaded: true, isSignedIn: false, userId: null, getToken: async () => null }`
- `ClerkProvider` and `Protect` render their children unchanged
- `SignIn`, `SignUp`, `PricingTable` all render `null`

### `lib/auth-server.ts` (server shim)

- `auth()` returns a stub with `userId: null`, `getToken`, and a no-op `protect`
- `currentUser()` returns `null`
- `clerkClient()` stubs `.users.getUser`, `.users.updateUserMetadata`, `.apiKeys.create`
- `clerkMiddleware` and `createRouteMatcher` are passthroughs

### `lib/dev-flags.ts`

- `DISABLE_AUTH = process.env.NEXT_PUBLIC_DISABLE_AUTH === "true"`
- `DISABLE_BILLING = process.env.NEXT_PUBLIC_DISABLE_BILLING === "true"`

### `proxy.ts`

Middleware with no auth checks. All routes are public; the Clerk middleware was removed.
Its matcher catches everything except static assets.

### The `"x"` owner

With auth disabled, there is no user id, so `app/actions/projects.ts` reads and writes
projects under the literal owner string `"x"` (see `getProjectsByUser("x")` and project
creation). Any local project you see in the sidebar is owned by `"x"`.

Note the asymmetry: the **platform** API routes (deploy, billing, chat-to-backend) still
call the real `@clerk/nextjs` server helpers and forward Clerk JWTs as bearer tokens to
external backends. So the client is Clerk-free but several server routes assume Clerk. In
pure local mode you exercise the universe half, which never hits those routes.

## Routes under `app/`

### Top level

| Path | Type | Renders |
| ---- | ---- | ------- |
| `app/page.tsx` | client | Home: welcome header + three "create project" cards (OpenClaw, Claude Code, Blank Canvas) linking to `/projects/create/*` |
| `app/launchpad/page.tsx` | client | Legacy deployment dashboard: `DeploymentTable` fed by `/api/get-deployments`, row actions via `useDeploymentActions`, access sheet + port popover |
| `app/projects/page.tsx` | server | Redirect to `/` |
| `app/projects/[...slug]/page.tsx` | client | The project view. Resolves the project; if `type: "local"` it renders the universe (`LocalProjectView`), otherwise the chat editor (message list, input, context cards, history loader) |
| `app/projects/create/page.tsx` | client | Three template cards, same as home |
| `app/projects/create/openclaw/page.tsx` | server | Card hosting `OpenClawProjectForm` (name, Anthropic key, gateway token, IDE, volume, optional Telegram/WhatsApp) |
| `app/projects/create/claude-code/page.tsx` | server | `ClaudeCodeProjectForm`, same shape with a Claude Code gateway token |
| `app/projects/create/blank-project/page.tsx` | server | `AddBlankProjectForm` (name, optional GitHub repo + token, IDE, volume) -> `createProjectAction` |

### Template group `app/(templates)/`

| Path | Type | Renders |
| ---- | ---- | ------- |
| `(templates)/templates/page.tsx` | client | Hero + tabs (Templates / Coming Soon) + grid: AI Coder (beta, disabled), Knowledge Base (beta, disabled), n8n, Gaia (Phi-3-mini). "Launch Now" links to `/templates/{n8n,gaia}` |
| `(templates)/create/page.tsx` | server | Two options: from scratch (`/create/blank-template`) or from a template (`/templates`) |

### Billing and auth callbacks

| Path | Type | Renders |
| ---- | ---- | ------- |
| `app/pricing/page.tsx` | client | Pricing table (the shim renders `null`, so a skeleton fallback shows); reads `?message=subscription_required` |
| `app/sign-in/[[...sign-in]]/page.tsx` | server | Centered `<SignIn/>` (shim -> null) |
| `app/sign-up/[[...sign-up]]/page.tsx` | server | Centered `<SignUp/>` (shim -> null) |
| `app/subscription/success/page.tsx` | client | Success card, shows Stripe `?session_id`, 5s countdown then redirect to `/` |
| `app/subscription/failure/page.tsx` | client | Failure card, shows `?error`, retry / back |
| `app/payment-method/success/page.tsx` | client | Success card, 5s countdown to `/billing` |
| `app/payment-method/failure/page.tsx` | client | Failure card with error alert |

The success / failure pages use `Suspense` around the part that reads search params (a
Next.js requirement for `useSearchParams`).

## Sidebars at the layout level

Both rails are the same `components/app-sidebar.tsx` with a `side` prop. Detail of the nav
sections lives in [Components and client state](/observations/xo-swarm-frontend/components-and-state),
but the layout-level contract is:

- **Left** carries live work: Add Data, Live XO, the Agents ("X") section, My Projects.
- **Right** is project-scoped and read-only-ish: Add Energy, Past XO, the project's
  Footprint (files) and Timeline (commits) tree.
- The logo header toggles the sidebar; it does not navigate.
- A separate `components/project-sidebar.tsx` exists but is largely superseded by the
  two-`AppSidebar` arrangement; it only toggles the canvas `files` pane.

### Gotcha: do not RTL-mirror the right sidebar

The shadcn sidebar primitives bake in physical classes (`text-left`, absolute `right-3`
actions, left borders, `pr-8` reserves) that `dir="rtl"` does not flip, so it ends up
misaligned. A real mirror needs per-row `flex-row-reverse` plus right-aligned text on the
menu buttons. The blunt `dir=rtl` attempt was reverted.
