**XO is workspaces for AI agents.** Not a chat wrapper and not a single app: a substrate
that gives an agent a runtime, memory, files, tools, and a chat surface, all in one
portable container, plus a platform to launch and manage many of those containers at once.

The single most important thing to hold in your head: XO is **two layers that stack, not
two products side by side.**

## The two layers

### XO Coworker: the workspace (the unit)

A containerized agent workspace: runtime + memory + files + tools + chat surface, bundled
into one portable image. The same image runs unchanged on a laptop, in a remote sandbox,
in a Coder workspace, in a raw Docker container, in a Vercel Sandbox, or any future
container host. The trust boundary follows wherever you run it.

### XO Swarm: the platform (the fleet)

Launches and manages many Coworker workspaces across whatever infra you point it at. It
owns identity, billing, observability, the integrations (Linear, GitHub, Slack, WhatsApp),
the templates (Eliza, Gaia, n8n, custom characters), and the UI to browse, start, and chat
with running workspaces.

> Coworker is the unit. Swarm is the fleet manager. A Coworker workspace runs the same way
> whether it is on a laptop or in a cloud container; Swarm is what points many of them at
> an infra provider and keeps track.

## The four product repos

These are the actual product. Everything else in the workspace is infrastructure for the
agents the product runs. The repos are **paired**: a frontend and a backend per layer.

| Layer | Frontend | Backend | What the pair is |
| ----- | -------- | ------- | ---------------- |
| Workspace | `xo-coworker` | `xo-cowork-api` | The Coworker workspace: chat surface + in-workspace control plane |
| Platform | `xo-swarm` | `xo-swarm-api` | XO Swarm: platform UI + cloud control plane |

### `xo-coworker`: workspace chat surface (Tauri)

A native desktop app (Tauri) that is the chat surface for a single Coworker workspace. A
bridge component reads OpenClaw's file-based session storage at `~/.openclaw/agents/*` and
translates it for the frontend. Heavy consumer-grade UI (MUI + Radix + Tanstack Query +
Zustand + documents, charts, code, multilingual). It talks to `xo-cowork-api` running
inside that workspace, wherever the workspace lives.

### `xo-cowork-api`: in-workspace control plane (FastAPI)

Runs **inside** a Coworker workspace and brokers the coding runtimes (`ClaudeCodeClient`,
`CodexCodeClient`), converting a frontend `agent_type` into `/skill-name` for Claude or
`$skill-name` for Codex. It manages sessions, files, full-text search, secrets, memory,
and channels (a `cowork_agent/` subsystem of routers). It does Clerk browser auth with a
poll-token flow that mints tokens for upstream calls to `xo-swarm-api`, so a workspace
knows who its user is. Its README is outdated (claims a "thin Claude Code wrapper"); the
file structure is the truth.

### `xo-swarm`: platform UI (Next.js)

Internally named `eliza-agent-builder`. The launchpad to start and interact with Coworker
workspaces, provider-agnostic by design (Coder is wired today; Docker and Vercel Sandbox
are the natural next adapters). Templates define what kind of workspace gets launched. This
is the repo the rest of these observations dig into, including a local-first "universe"
visualization layered onto it. See
[the xo-swarm frontend deep-dive](/observations/xo-swarm-frontend).

### `xo-swarm-api`: platform control plane (FastAPI)

Multi-tenant project + agent + sharing state, MCP integrations as first-class (Linear,
GitHub, Slack, custom; in `mcp_configs.json`), OAuth-flow management for connected tools,
S3 storage, Postgres-backed state, Clerk multi-tenant auth, and instruction templates per
agent and per team. Its README is badly outdated (still says "Multi-User PDF Q&A System");
RAG via Qdrant is now just one capability among many.

## How it holds together

- **Auth is Clerk everywhere.** `xo-cowork-api` mints `xo-swarm-api` tokens through a
  poll-token browser flow, so a workspace can pull state from the platform on behalf of its
  user.
- **The skill model is shared across runtimes.** The frontend sends `agent_type`; the
  backend converts it to `/skill-name` (Claude) or `$skill-name` (Codex).
- **OpenClaw is the open-source agent runtime.** It runs inside a Coworker workspace;
  `xo-cowork-api` brokers it; the Coworker desktop reads its file storage. Claude Code CLI
  and Codex CLI are the other brokered runtimes.
- **Cloud hosts are pluggable.** Swarm's launchpad is provider-agnostic; Coder is the
  adapter wired up today.
- **MCP is how XO integrates external tools** (Linear, GitHub, Slack, custom), configured
  in `xo-swarm-api/mcp_configs.json`.

```
            XO Swarm  (platform / fleet)
   xo-swarm  +  xo-swarm-api
        |  provisions / starts / connects
        v
            XO Coworker  (the workspace / unit)
   xo-coworker  +  xo-cowork-api
        |  brokers
        v
   Runtimes: OpenClaw (OSS) | Claude Code CLI | Codex CLI
```

## Everything else is supporting infrastructure

The rest of the workspace supports the four product repos and should be treated as infra,
not product:

- **Customer-facing surface:** `xo-main` (the `xo.builders` marketing + auth site),
  `xo-docs` (public product docs), `xo-room` (investor / partner data room; the cleanest
  README and the canonical XO story for outsiders).
- **Customer-extensible templates:** `xo-agent-template` (what customers fork to configure
  an agent's personality: `SOUL.md`, `IDENTITY.md`, `AGENTS.md`, `MEMORY.md`, `skills/`),
  `xo-docs-template` (branded Fumadocs boilerplate).
- **Commerce:** `xo-billing` (a decoupled Stripe service in Bun/TypeScript).
- **Internal / team:** `xo-internal` (the team wiki, a Notion replacement).
- **Alternative / iteration UIs:** `xo-org` (dual-mode org/agent workspace UI, where future
  product may converge), `xo-agent` (an early WebSocket pass, likely superseded),
  `xo-data-room` (a lighter early `xo-room`).

Two non-XO buckets sit at the workspace root and should be ignored unless a request names
them: `clients/` (client work) and `experiments/` (side projects and prototypes).

## Brand, in one line

The mark is two pairs of chevrons forming an "XO", outer pair white, inner pair lime green.
The canonical brand color is **XO lime green `#83d63a`** (about `hsl(92, 66%, 53%)`), with a
darkened `hsl(92, 60%, 28%)` variant used on light surfaces for contrast. Positioning, at
its cleanest: "the infrastructure layer for AI agents" / "workspaces for AI agents".

## Reading guide for the next agent

1. The two layers **stack**; they are not parallel SKUs.
2. When unsure which repo does what, the workspace map is canonical. **READMEs lie**
   (notably `xo-swarm-api`'s and `xo-cowork-api`'s); trust the file structure.
3. The four product repos are paired; a frontend change often needs a matching backend
   change.
4. Default everything server-side (no client-side external API calls without a concrete
   reason the server cannot intermediate).
